# 发售信号（Release Signal）

一个面向个人使用的新游戏发布雷达。项目参考了 [MY-ani_web](https://github.com/shengtokyonokouu-cpu/MY-ani_web) 的“档期 + 个人收藏 + 来源追踪”思路，重新设计为游戏情报与游玩档案应用。

当前资料快照：`2026-08-19`。初始目录包含日本、欧美开发团队的已发售、已定档和开发中作品，全部记录至少一个可追溯的官方来源。

## 已实现

- 已发售、待发售、开发中严格分层，不给未定档作品猜日期。
- 按平台、地区、状态、日期、四维均分与关键词筛选。
- 默认浅色主题，可一键切换深色主题并在本机保存偏好。
- 每次打开自动刷新 Wikipedia 本年度与下一年度游戏发布清单，并批量补全可用的游戏图片与简介。
- 核验档案与自动发现条目统一进入自适应网格，以 12 条一页分页浏览。
- 通过 Wikipedia / Wikimedia 公共索引按关键词继续动态检索目录外作品。
- 在线发现结果与官方已核验目录严格分层，不把公共索引自动写成事实。
- 连续发售日历与日期变更情报流。
- 每部作品都有开发商、发行商、国家/地区、平台、类型、适配理由和注意项。
- 每条日期与平台信息附官方出处、核验日期与证据说明。
- 玩法、剧情、画面、音乐四维评分可自行调整；待发售作品明确标为“期待值”。
- 愿望单、想玩/在玩/通关/搁置状态和私人笔记保存在浏览器 `localStorage`。
- 响应式桌面/手机界面、90%–120% 全局缩放、键盘关闭弹窗、减少动画偏好支持。
- 专属 Open Graph 分享卡及按访问域名生成的绝对分享地址。

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

默认打开 <http://localhost:3000/>。

## 验证

```bash
npm test
npm run lint
```

`npm test` 会先完成 Cloudflare 兼容构建，再检查：

- 首页可以服务端渲染且不残留启动模板；
- 每条游戏记录都有唯一 ID、HTTPS 来源、核验日期与证据说明；
- 已发售/待发售状态和资料快照日期一致；
- 未定档项目不允许写入推测日期；
- 所有四维初始值位于 1–10。

## 更新游戏资料

目录集中在 [`app/data/games.ts`](app/data/games.ts)。新增或更新作品时：

1. 优先查找开发商、发行商、Nintendo、PlayStation 或 Xbox 的原始页面。
2. 填写 `source.url`、`source.checkedAt` 与具体的 `source.evidence`。
3. 日期变化时更新游戏记录，并在 `signals` 中保留一条变更记录。
4. 没有官方日期时使用 `status: "development"` 和 `releaseDate: null`。
5. 运行 `npm run catalog:validate`。

媒体爆料只有在来源可追溯、与官宣明确分区时才应进入目录。当前快照没有达到收录门槛的传闻，因此不会为了填满“传闻”栏目而制造内容。

## 部署

应用基于 React 19、vinext、Vite 与 Cloudflare Worker 兼容输出：

```bash
npm run build
```

Cloudflare Pages 的高级 Worker 输出可通过 `npm run pages:build` 生成在 `dist/pages`，随后连接 GitHub 仓库或使用 Wrangler 发布到免费的 `*.pages.dev` 二级域名。项目也保留 `.openai/hosting.json`，用于兼容 Sites 构建与版本归档。

## 数据与隐私边界

- 游戏名称、商标和资料归各权利人所有，本项目只做个人信息整理。
- 四维分数是个人参考，不是媒体均分，也不声称客观。
- 愿望单、评分和笔记默认仅在当前浏览器保存，没有账号与跨设备同步。
- 外部链接打开官方页面；本站不代理商店交易、不收集付款信息。
- 年度发布索引与动态检索都由浏览器直接请求 Wikipedia API；结果在本机短期缓存，本站不保存检索关键词，缩略图版权与许可以对应 Wikimedia 页面为准。

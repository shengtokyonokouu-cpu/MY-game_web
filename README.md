# 发售信号（Release Signal）

一个公开可用的个人游戏资料库：发现新作、查看发布安排、收藏游戏，并按玩法、剧情、画面、音乐记录自己的体验。参考 [MY-ani_web](https://github.com/shengtokyonokouu-cpu/MY-ani_web) 的档期与个人记录思路。

- 网站：[release-signal.pages.dev](https://release-signal.pages.dev/)
- 源码：[MY-game_web](https://github.com/shengtokyonokouu-cpu/MY-game_web)

## 使用体验

动态 IP 引擎现已改为 D1 数据库驱动：候选挖掘、Wikidata 实体核验、热度阈值升格、异步历史补标和动态频道排序。原 8 个频道只是初始化种子，不再是上限。后台调度无需网页保持打开；详细流程、API、限制与维护方式见 [动态 IP 引擎](docs/ip-engine.md)。

- 发现页直接显示游戏网格，12 条一页；支持平台、类型、地区、发售状态筛选和日期、名称、个人评分排序。
- 首屏内置 2026 / 2027 年度清单的 1,400 多部游戏，不依赖第三方网络请求才能展示内容。
- 打开网站及使用期间每 30 分钟更新目录，支持手动刷新；失败时保留快照并提示。
- 搜索同时覆盖本机目录、任天堂最新 Direct、三种语言的 Steam 商店和中 / 日 / 英 Wikipedia，单一来源不可用不会掩盖其他结果，并显示各来源的匹配数和状态。
- 游戏卡片、详情和日历列表展示中 / 日 / 英名称，详情可逐个查看名称出处；名字缺失时不猜译。翻页时按需补充同一 Steam 游戏身份下的地区名称与图片。
- 支持「薬屋のひとりごと」「藥師少女的獨語」「The Apothecary Diaries」以及「昨天 NS 直面会」「Nintendo Direct 2026.9.9」；昨天 / 今天按中国时区解析，不永久写入游戏别名。
- 游戏架支持想玩、在玩、已通关、搁置；四维分数初始为空，均值只计入实际填写的维度。
- 发售日历支持跨月、平台过滤、选择日期、打开详情，分别展示不同平台版本的发布记录。
- 详情包含资料出处、检索或核验日期、简介、游戏版本与个人记录；关闭未保存的编辑会提醒。
- 设置中可导出 / 导入 JSON 备份，同一游戏保留较新的修改；自动迁移旧版本的本机收藏、评分和笔记。
- 默认浅色，可切换深色；支持 90%–150% 界面缩放、舒适 / 紧凑密度、响应式手机导航和键盘操作。
- PC 详情弹窗显式固定居中，不再依赖被样式重置覆盖的浏览器默认边距；手机采用全屏弹窗。
- 游戏新闻接入 8 个公开订阅源：PlayStation Blog（英文、日文、繁体中文）、Xbox Wire（英文、日文）、Gematsu（英文）、4Gamer（日文）、巴哈姆特 GNN（中文）。每 5 分钟检查更新，可按语言 / 来源 / 官方 / 媒体 / 访谈 / 传闻筛选，保留原文和原始日期。
- GitHub 账号登录后，收藏、评分、游玩状态和笔记保存到 Cloudflare D1；其他设备每 30 秒检查更新，本机编辑自动上传。
- 并发修改采用版本校验和三方合并；同一款游戏有冲突时要求选择版本，删除不会被旧设备自动恢复。首次登录可自行合并本机游戏架。
- 未处理的同步冲突会随账号缓存保存，刷新后仍需确认；冲突面板可对照四维评分、游玩状态和完整笔记。缓存损坏时暂停写入和同步，保留原始记录供导出恢复。
- 新闻缓存经过结构、日期和来源链接校验；重复刷新合并处理，断网重连后补取更新，搜索会回到第一页。

## 数据真实性与限制

### 来源分级

1. **官方来源**：原有 21 部精选资料保留 2026-08-19 的历史核验日期；新增发行商公告单独记录核验日期。另外自动读取任天堂最新 Direct 的公开目录与官方图片，保留发布会关联。任天堂日本目录中的日期仅代表日本任天堂版本，不推断其他平台。
   《藥師少女的獨語 ～真假皇弟～》使用发行商中日英官网名称与平台公告，2026-09-10 核验。
2. **商店资料**：动态查询发行商维护的 Steam 页面；日期与平台只代表 Steam 版本，不据此推断主机独占情况。
3. **公共索引**：Wikipedia 年度清单与游戏条目。明确标记尚待官方核验；不承诺收录全球全部游戏，也不将公共索引伪装成官宣。

精确日期、季度、年份和未定档分别处理。不从“Q4”推算某一天。旧的计划日期经过后，若没有新证据，标为“待复核”，不自动断言已上市。年度清单的过去日期仍是索引记录，不等同于本站独立核实。

新闻由 GitHub Actions 约每 3 小时抓取公开 RSS；页面每 5 分钟检查静态快照。检查更新不等于源站一定有新稿。标题保留原文，不自动生成未经核实的翻译或事实。官方公告与媒体报道分开标记；访谈和传闻依据原标题的明确标记分类，不将媒体爆料视为已核实事实。自动来源失效时显示缓存及异常状态。人工整理记录和来源台账保留在可展开的归档中，并标明历史核验日期。国家、地区、平台等缺失信息仍显示待确认。

三语名称分别带来源类型（官方 / 商店 / 索引）。Steam 在某些地区会沿用英文原名；这不代表存在译名，也不等于游戏支持相应字幕。百科语言链接只用于同一作品的名称关联。暂时缺失的语言显示「暂无可靠名称」，可通过翻页、在线检索和后续快照更新补充；不承诺全球每部游戏都有三个官方本地化名称。

任天堂自动入口跟随官网当前 Direct，不猜测未来的发布会地址。若官网格式变化，显示来源异常并使用已发布快照；旧场次在快照中保留。完整地区标题优先，移植版、续作与本体不通过模糊匹配混合。媒体新闻不会自动变成“官方核实”的发售记录。

### 图片

封面来自游戏对应的 Nintendo Direct / 发行商官方页面、Wikipedia / Wikimedia 或 Steam 条目；精选可用封面随站点发布，历史目录图片优先预先补齐并直接加载来源图；少量近期未补齐封面仍使用同源按需解析。拒绝指向系列、清单、页面小节或其他作品的百科跳转；不以旧作的封面和中文名代替续作或新版。

封面地址失效时会重新解析对应条目；缺少可靠百科图源时尝试 Steam 完整名称匹配，并再次验证商店项目属于游戏。不同编号、重制版、原声带和模糊搜索结果不会当作同一作品。快照更新优先补充精选与近期游戏，其余按需查询；宁可明确缺图，也不展示无法确认的图片。

没有可靠图源或加载失败时，明确显示缺图状态。图片、名称、商标和原文版权归各权利人；图片来源可从 `app/data/covers.json`、`app/data/discovered.json` 与游戏资料链接追溯，使用及再分发应遵守对应权利人的条件。

### 隐私与持久化

未登录时个人游戏架仅保存在浏览器。GitHub 登录后，账号 ID、公开用户名和游戏架保存在本站 Cloudflare D1，游戏记录不会上传 GitHub，且不同账号由服务端身份隔离。主题与密度仍是设备偏好。首次登录不会擅自上传原有本机游戏架，需点击合并按钮。

登录采用授权码 + PKCE、浏览器绑定的一次性 state、HttpOnly / Secure / SameSite Cookie。会话有效期 7 天，可通过退出登录立即撤销；GitHub 令牌仅用来识别用户，不保存、不申请仓库权限。云端修改要求同源和 CSRF 校验，并以版本号避免并发覆盖。每个账号目前最多同步 1,000 款游戏、2 MB JSON。

本机缓存保留待同步修改；同步完成后退出登录会清理该账号缓存，未同步修改仍按账号隔离保存。请勿在不信任的共享浏览器存储私人笔记。登录限流仅短期保存 IP 的散列值，不保存原始 IP；Cloudflare 自身日志适用平台政策。

搜索词会通过本站接口转发到 Steam / Wikipedia，并可能暂存在 Cloudflare 缓存和平台请求日志中；请勿输入私人信息。外部页面另行适用其隐私政策。本站不处理商店交易或付款信息。

## 开发与验证

需要 Node.js >=22.13.0。

```bash
npm install
npm run dev
npm run typecheck
npm run lint
npm test
```

本地地址为 http://localhost:3000/。`npm test` 构建后检查服务端渲染、资料完整性、真实表格中的跨行 / 跨列单元格、日期精度、游戏身份去重、旧数据迁移和备份校验。

应用基于 React 19、vinext、Cloudflare Pages Advanced Mode Worker。服务端请求经过短期缓存，图片代理限制到明确允许的图片域名、栅格图片格式和 5 MB 大小上限，不提供任意 URL 代理。

主要接口：

- `GET /api/news`：聚合公开新闻源，保留发布时间和来源状态。
- `GET /api/auth/me|login|callback`、`POST /api/auth/logout`：GitHub 登录与会话。
- `GET /api/library`、`PUT /api/library`：需身份验证的账号游戏架与版本校验。
- `GET /api/catalog`：本年度及下一年度发布目录，失败返回自带快照。
- `GET /api/search?q=...`：在线游戏检索，搜索词 2–100 字符。
- `GET /api/names?ids=...`：一次最多为 3 款已收录游戏按精确商店身份补充地区名称，不修改个人记录。
- `GET /api/details?title=...&lang=en|zh|ja`：按需游戏简介。
- `GET /api/cover?title=...`、`GET /api/image?url=...`：封面解析与同源图片传输。

## 公共目录更新（当前方案）

公共抓取已迁移到 GitHub Actions 静态快照，Cloudflare 高频 alarm 已关闭。每 3 小时新闻、每日新作、每周全量系列；完整架构、数据边界和运维说明见 [PUBLIC-CATALOG.md](docs/PUBLIC-CATALOG.md)。角色 pane、IP 全历史年表使用 `/data/` 或公共数据分支，不运行 D1 全库扫描。下文旧目录脚本仅用于手动维护首屏兼容快照。

## 更新首屏兼容资料

```bash
npm run catalog:refresh
npm run catalog:validate
```

更新脚本解析当年与下一年度清单及最新 Nintendo Direct，以同一百科条目的语言链接补齐中文、日文和英文名称，再为近期游戏补查精确匹配的 Steam 地区名称与图片。保留旧快照里的可用名称和图源，写入随站点发布的快照。仅刷新近期名称可运行 `node --experimental-strip-types scripts/enrich-names.mjs`。运行时刷新不修改 Git 仓库；如需将最新资料固化到首屏快照，运行脚本并重新发布。

人工精选位于 `app/data/games.ts`，首发公告的跨语言身份桥接位于 `app/data/announcements.ts`；新闻源配置位于 `app/lib/news-sources.ts`（服务端拉取和客户端安全校验共用）。修改时优先使用发行商、开发商或平台原始公告，更新来源、核验日期与证据说明；日期变更可在 `signals` 中留档。未有官方日期时使用 `releaseDate: null`，不填写猜测日期。

## 部署到 Cloudflare Pages

```bash
npm run pages:build
npx wrangler pages deploy dist/pages --project-name=release-signal --branch=main
```

发布目录为 `dist/pages`，公网地址使用 `pages.dev` 域名，不依赖 ChatGPT 登录。保留原有 `.openai/hosting.json` 的逻辑 DB 声明；当前交付目标是 Cloudflare Pages。

账号部署须配置 D1 绑定 `DB`，运行 `npm run db:migrate`，并在 Cloudflare Pages 的服务端密钥中设置 `GITHUB_CLIENT_ID` 和 `GITHUB_CLIENT_SECRET`。密钥未配置时，登录入口明确提示未就绪，不模拟登录或伪装同步成功。

GitHub OAuth 应用的首页为 `https://release-signal.pages.dev/`，回调为 `https://release-signal.pages.dev/api/auth/callback`，不启用通配回调或 Device Flow。只在正式域名发起登录；预览域名不提供账号服务。真实密钥不得提交到 GitHub，`.dev.vars.example` 仅展示本地配置名称。

数据库结构位于 `db/schema.ts`，通过 `npm run db:generate` 生成 Drizzle SQL；已执行的迁移不可修改，仅追加新迁移。测试使用内存 SQLite，不读取或写入真实用户的记录。
